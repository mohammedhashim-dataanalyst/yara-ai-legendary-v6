# Yara 3D Character Pack

## Architecture findings

This project is Kotlin + Jetpack Compose and previously had no 3D renderer. The included `YaraHeadRenderer` is a dependency-free OpenGL ES 2.0 procedural head with a UV-sphere head, neck, shoulders, hair cap, eyes, mouth, depth testing, perspective projection, and Phong-ish fragment lighting. `YaraAvatarView` supplies drag rotation and idle sway; `LipSync` supplies coroutine mouth frames.

## Recommended production pipeline

Blender -> rig and texture the character -> export VRM 1.0 with ARKit 52 blendshapes -> integrate with Filament/SceneView or another reviewed Android renderer. Keep the procedural renderer as a no-asset fallback.

## Required asset list

- Licensed photoreal or stylized base mesh, head, neck, shoulders, hair, eyes, teeth, tongue, and clothing
- PBR textures: base color, normal, roughness, metallic, and optional subsurface maps
- Face rig, body rig, eye targets, eyelid controls, visemes, and expression controls
- ARKit-compatible 52 blendshape morphs, avatar thumbnail, licensing metadata, and LOD meshes
- VRM 1.0 metadata, humanoid bone mapping, spring bones, and physics limits

## Structured integration prompt

> Replace the procedural Yara renderer with a licensed VRM 1.0 or GLB asset. Add the asset under app assets, load it only through a reviewed Filament/SceneView dependency, preserve the `YaraAvatarView` public surface, map ARKit 52 names above to expression controls, map `LipSync` jaw/mouth frames to `jawOpen`/viseme weights, retain drag yaw/pitch, idle sway, blink, brow, emotion selection, TTS completion, and lifecycle-safe disposal. Do not embed an unlicensed reference likeness. Add offline fallback and document asset license and APK size impact.

A photoreal model matching a reference photo cannot be generated by code; it must be produced in Blender or obtained under an appropriate license.

## Legendary runtime

The app includes a procedural OpenGL ES avatar (`YaraHeadRenderer`), Canvas ambient scene renderer (`ambient/SceneView`), and particle emote engine (`ambient/EmoteEngine`). A real model drop-in must supply a licensed VRM/Blender asset with head, eye, mouth, brow, and body blend-shape contracts; the current renderer remains the dependency-free fallback.
